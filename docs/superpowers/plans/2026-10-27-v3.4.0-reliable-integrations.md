# INI Brain 3.4.0 Reliable Integrations Implementation Plan

> **For agentic workers:** Execute inline with `executing-plans`, test-first. Engineering choices and implementation through verification were explicitly delegated by the user; no additional design gate. No commits, pushes, publishing, real client configuration writes, or nested worktree edits.

**Goal:** Ship a verified 3.4.0 compatibility/reliability VSIX without losing shared memory, selecting another project's workspace, or damaging client configuration.

**Architecture:** Keep the VS Code-independent TypeScript core. Serialize memory mutations with an exclusive filesystem lock and atomic sibling-file rename; compaction participates in the same transaction. Resolve workspace afresh on every call, reject ambiguous/unsafe selections before project tools, and correlate MCP roots responses by pending request ID. Integrations emit native client shapes; configuration updates preserve user-owned fields, validate before writing, and back up originals. Unsupported automatic integration is reported honestly.

**Tech Stack:** Existing TypeScript/Node stdlib, CJS smoke tests, PowerShell installer; use existing dependencies only.

**Spec:** `.specify/specs/3-4-0-reliable-zadloop-and-opencode-integration/spec.md`.

## Global Constraints

- Preserve all baseline dirty work, hand-authored guidance, upstream checksums and licenses. Stop on unfamiliar overlapping concurrent changes.
- Never install dependencies or write global configuration during verification; use repository-local fixtures.
- Do not cache the last per-call workspace; an explicit invalid path must never fall back.
- No destructive migration, guessed ZadLoop skill folders, giant injected prompts, or UI expansion.
- Advanced Code Intelligence remains opt-in. Real client UI behavior is not inferred from protocol tests.

## Review Focus

- A live memory lock must never be evicted based on age; bounded contention fails without modifying data.
- Valid legacy entries retain normalization and metadata, but corrupt/wrong-shape files remain byte-for-byte intact.
- No-roots desktop clients cannot reveal the current project; every project call needs an explicit workspace.
- Existing user env, permissions, server options and JSONC comments must survive installation, or installation must refuse unchanged with manual merge instructions.
- Multi-root requests, late/unknown roots response IDs, project switches and empty explicitly selected projects must not cross-contaminate.

## Task 1 — Shared memory integrity

Files: `src/core/memoryStore.ts`, `src/core/memoryCompactor.ts`; new `scripts/memory-reliability-smoke.cjs`; existing memory smoke and package script.
Interfaces: retain `save/search/list/listAll/replaceAll`; add `transaction<T>(update: (entries: MemoryEntry[]) => { entries?: MemoryEntry[]; result: T }): Promise<T>` so compaction computes and commits under one lock. A sibling exclusive lock covers same-process and multi-process writers. Only ENOENT means empty; malformed arrays/entries and IO errors throw. Atomic write uses unique sibling temporary file, sync, rename, cleanup. Recovery of abandoned locks is manual after confirming all writers stopped.
